# int-341: the painted relic icons

Brought in PR #341: 48 relic paintings (`art-source/relics/raw/`, 512x512 RGBA with a clear background, original art made with an image model) and `tools/relics/`. This is the "Art plan" of `relics-redesign.md`, with the prompts and tools of `relic-art-prompts.md` (branch `art/gemini-relics`; `art-source/relics/PROMPTS.md` holds the prompts used).

- **Mapping.** The paintings are named for the relic's name (`the-first-banner.png`). The relics keep their old ids in code (`banner`, `scholarScroll`...), and the fifth column of `tools/relics/relics.json` is the OLD id a relic replaced, which is not always the live one. So `tools/relics/relic-ids.json` maps each painting to its live id by name (all 48 matched; a test checks every id in `RELICS` has a painting and the other way round).
- **Cutting.** `tools/relics/import-relic-icons.py` trims each painting to its visible pixels and fits it into a 128x128 WebP with a 4% margin: `src/art/relics/<id>.webp` (366 KB in all).
- **Loading.** By URL, like the gear and shop art: `build.mjs` copies `src/art/relics/` to `out/web/relics/` and lists the files for the service worker, so they play offline. `relicIcon(id)` in `src/render/items.ts` gives `relics/<id>.webp` for a painted relic and keeps the old 16x16 tile as the fallback for any without one.
- **Drawing.** Every page rule draws icons pixelated; a painting would blur into blocks, so `iconImg` adds a `painted` class and `relicCard.css` draws it smooth. The fight's mark over a hero (`fx.ts`) loads the painting with linear scaling at the size the tile had.
- Nothing about the rules, rarity frames or the order of the relics changed. `art/gemini-relics`'s tool (`paint-relics.py`) came with the PR and is unused here.
