# The Android app

The game is also an Android app (Capacitor wrapping `out/web`), for beta play on a phone. It is the same page as the
web version: it starts with a fresh save of its own and plays fully offline (every file is bundled in the APK; the
page skips the service worker when it runs in the app). The web build on GitHub Pages is untouched.

## What is where

- `capacitor.config.json`: app id `com.hpatter9.lastkeep`, name, `webDir: out/web`.
- `android/`: the Capacitor project. Portrait only (manifest), full-screen with the system bars hidden
  (`MainActivity.java`), screen kept on, the game's icon in the launcher sizes, a plain black splash with the icon.
  The web files in `android/app/src/main/assets/public` are generated by `cap sync` and not committed.
- `src/appUpdate.ts`: `inApp()` (true only inside the app) and the "Update available" check: one fetch of
  `api.github.com/repos/hpatter9/legends-of-the-fall/releases/latest` at start, ignored quietly when offline or on any
  error. If the latest tag is newer than the running version, Settings, About shows an "Update available" row with a
  link to that release page.
- `.github/workflows/android.yml`: builds the APK and publishes the release.

## Installing on the phone (once)

1. On the phone, open the repo's Releases page (github.com/hpatter9/legends-of-the-fall/releases) and open the newest
   release.
2. Tap the `.apk` file under Assets to download it.
3. Tap the download. The first time, Android asks to allow "Install unknown apps" for the browser you used: switch on
   "Allow from this source", go back, and tap Install.
4. Open "Legends of the Last Keep". To update later, install the newer APK over the old one (the save stays, as long as
   both are signed with the same key: see below).

## Publishing a new version

After a merge (the director bumps `package.json` as usual), tag it and push the tag:

```bash
git tag v0.320.0   # the same number as package.json's version
git push origin v0.320.0
```

The workflow runs `npm ci`, `npm run web`, `cap sync`, `./gradlew assembleRelease`, and attaches
`legends-of-the-last-keep-<version>.apk` to a Release named after the version. It can also be started by hand
(Actions, Build the Android app, Run workflow); it then uses package.json's version for the tag. The Android
`versionCode` is `major*1000000 + minor*1000 + patch`, so each release is higher than the last.

## Signing

With no secrets the APK is signed with the debug key, which installs fine but is a different key on every CI machine, so
**an update can fail to install over an older build** ("App not installed"); uninstall first (this loses the save).
For smooth updates, make one key and add four repository secrets (Settings, Secrets and variables, Actions):

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | the keystore file, base64 (`base64 -w0 release.keystore`) |
| `ANDROID_KEYSTORE_PASSWORD` | the keystore password |
| `ANDROID_KEY_ALIAS` | the key alias (`lastkeep` below) |
| `ANDROID_KEY_PASSWORD` | the key password |

One-time command (keep the file and passwords safe; never commit them):

```bash
keytool -genkeypair -v -keystore release.keystore -alias lastkeep -keyalg RSA -keysize 2048 -validity 10000
```
