# Painted tavern and strongest company

Owner approved a painted tavern using the shared materials from merged [PR #425](https://github.com/Hpatter9/legends-of-the-fall/pull/425), with the five strongest heroes at the time. Branch: `design/painted-tavern`, `/workspace/legends-of-the-fall`, based on that PR's integrated 0.390.0 head. No version bump, merge or deployment.

`PaintedTavern` replaces the Heroes tab's pixel room. The new hearth painting is an empty environment; the existing transparent character illustrations are separate, tappable guests. The follow-up [seated art pass](tavern-poses.md) puts the strongest two guests in foreground armchairs and the remaining three nearer the hearth, using dedicated resting paintings. Names are available on intentional hover/focus, with a list below showing class, level, Power and available upgrades. All heroes opens the unchanged full roster.

`render/tavernCompany.ts` chooses up to five owned catalogue heroes using the existing dossier `kindPower` (level, rank, equipment and talents), highest first. Equal powers retain catalogue order. Every home refresh recomputes guests, including after progression/equipment changes; existing character image nodes are retained. The active party does not constrain selection. Fewer than five recruited heroes means fewer guests, with no locked hero or placeholder added. This is presentation only: no simulation, saves or power calculations changed.

The page reuses the actual `combat-panel.png`, `combat-skill.png`, `combat-portrait.png` and service motifs from #425. Full roster and detail sheets keep their existing presentation and handlers. Upgrades, quests, quest board, Gwen, Hester's shop/travellers, trophies and the conditional Elders' table remain accessible through labelled service buttons. The quest board includes offers from patrons outside the five displayed guests. One painted hearth replaces the three-room pan; services have explicit buttons rather than hidden room hotspots. The room has no animation loop, so reduced-motion and hidden-page use require no background drawing.

Artwork: `art-source/tavern/cozy-room-source.png` (following the first `hearth-source.png` study), imported losslessly as `src/art/ui/tavern-hearth.png`, credited in `CREDITS.md`. OpenAI image generation painted the empty room. The existing build UI loop copies and precaches it for offline play. No generated UI text or fixed heroes are baked into the environment.

Validation complete: typecheck and production web build pass; all five focused test files pass. All 40 browser checks pass across 393×852, 360×780 and 412×915, including reduced motion, offline scene/character loading, guest replacement after strength changes, fewer-than-five saves, full roster, hero details, quest log, shop, upgrades and 44px service/hero targets. All three portrait screenshots and the services view were visually reviewed. No page errors or horizontal overflow observed. Reproduce with `npm run typecheck`, `npm run web`, `npm test -- tavern-company power ui-standard` and `node tools/tavern/painted-checks.mjs` (installed Playwright and Chromium paths may vary). Preview fixtures are isolated saves, not the owner's live company. Screenshots: `../samples/painted-tavern-393.png`, `../samples/painted-tavern-360.png`, `../samples/painted-tavern-412.png`.
